34. Subquery   → NO data stored → one query only
               → Non-correlated: inner runs once, independent | used in SELECT, FROM, WHERE, JOIN, IN, ALL, ANY, EXISTS
               → Correlated: inner runs per outer row (slower) | WHERE salary > (SELECT AVG(salary) FROM emp e2 WHERE e2.dept = e.dept)
               → use: quick filter, small task | gets unreadable as you nest more

35. CTE        → NO data stored → one query only
               → Standalone | Multiple | Chained (one uses another) | Recursive (start + repeat + stop)
               → WITH Numbers AS (SELECT 1 AS n UNION ALL SELECT n + 1 FROM Numbers WHERE n < 5) SELECT n FROM Numbers → 1,2,3,4,5
               → referenced 2 times = runs 2 times | SQL Server max 100 levels by default
               → use: readable big queries, hierarchy/org chart, fill missing dates, sequences

36. View       → NO data stored → permanent, always live
               → saved query, runs fresh every time | CREATE / ALTER / DROP VIEW
               → materialized view = exception, stores data and refreshes (daily dashboards)
               → use: simplify (hide JOINs), security (only needed rows/columns), consistency, original table untouched

37. Temp table → YES, stored in tempdb → until session ends
               → SELECT CustomerID, SUM(Amount) AS Total INTO #MonthSales FROM Orders GROUP BY CustomerID
               → #temp = only me | ##temp = everyone | CTE = one query, temp table = whole session
               → use: test logic, calculate once and reuse, break big query into steps, heavy transformations

38. CTAS       → YES, frozen copy in database → permanent until dropped
               → SQL Server: SELECT * INTO new_table FROM old_table | Fabric/Synapse/Postgres/Snowflake/BigQuery: CREATE TABLE new AS SELECT ...
               → snapshot, doesn't update when source changes | no keys/indexes copied | new table must not exist
               → use: backup before UPDATE/DELETE, save cleaned data, ETL staging, freeze month-end numbers

39. Stored proc → NO data stored (runs code) → permanent, saved in database
                → CREATE PROCEDURE LoadSales @Month DATE AS BEGIN ... END | EXEC LoadSales @Month = '2026-09-01'
                → takes parameters | INSERT/UPDATE/DELETE | IF/ELSE, loops, TRY/CATCH
                → use: multiple steps in one call, ETL, scheduled nightly jobs

→ A view answers a question, a stored procedure does a job.
→ Choose based on who needs the data and for how long, not just speed.
